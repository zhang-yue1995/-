## 项目概述

### 产品名称
**鑫速录** - 企业财务报表自动化填报与智能分析系统

### 产品定位
基于OCR识别和AI技术的财务报表自动化处理平台，支持：
- 财务报表扫描/拍照上传与自动识别
- 三大财务报表（资产负债表、利润表、现金流量表）智能解析
- 财务指标自动计算与健康度评估
- AI驱动的财务分析与风险预警

### 目标用户
1. **C端用户（小程序）**: 企业财务人员、会计事务所审计人员
2. **B端用户（管理后台）**: 企业管理者、财务总监、风控专员

### 核心价值
- ⚡ **效率提升**: 报表录入时间从30分钟缩短至3分钟
- 🎯 **准确率高**: OCR识别准确率≥95%，人工复核后达99%+
- 📊 **智能分析**: 30+财务指标自动计算，五维健康度评估
- 🔔 **风险预警**: 实时监控异常指标，提前发现潜在风险

   - 直接打开对应报表的详情页

#### 状态定义
```typescript
enum ProgressStep {
  IMAGE_UPLOAD = '图片上传',
  OCR_RECOGNITION = 'OCR文字识别',
  TABLE_PARSING = '表格结构解析',
  FIELD_MAPPING = '字段映射匹配',
  DATA_VALIDATION = '数据校验',
  REPORT_GENERATION = '生成分析报告'
}

interface ProgressStatus {
  currentStep: ProgressStep;      // 当前步骤
  progress: number;               // 0-100 总体进度
  estimatedTimeRemaining: number; // 预估剩余秒数
  steps: Array<{
    step: ProgressStep;
    status: 'completed' | 'running' | 'pending';
    message?: string;             // 步骤详细信息
  }>;
}
```

#### 交互逻辑
1. **轮询机制**: 每2秒请求一次进度接口 `/api/v1/progress/{taskId}`
2. **WebSocket推送**（可选）: 实时接收进度更新
3. **完成后行为**: 
   - 自动跳转到 [03 新增报表/建档信息]
   - 或直接到 [04 识别结果复核]（如果已建档）
4. **取消任务**: 
   - 调用取消接口终止服务端任务
   - 返回上一页并清理临时数据

#### 校验规则分类
```typescript
enum ValidationCategory {
  BALANCE_CHECK = '平衡性检查',      // 如: 资产=负债+权益
  LOGIC_CHECK = '逻辑一致性',        // 如: 营业收入>营业成本
  RATIO_CHECK = '比率合理性',        // 如: 流动比率在合理范围
  TREND_CHECK = '趋势异常',          // 如: 环比变动超过50%
  COMPLEteness = '完整性检查',        // 如: 必填字段不能为空
  FORMAT_CHECK = '格式规范性'         // 如: 数值格式正确
}

interface ValidationIssue {
  id: string;
  category: ValidationCategory;
  severity: 'error' | 'warning' | 'info';
  ruleName: string;                 // 规则名称
  description: string;              // 问题描述
  currentValue: number | string;    // 当前值
  expectedValue?: number | string;  // 期望值/参考值
  suggestion: string;               // 处理建议
  relatedFields: string[];          // 关联字段
  status: 'open' | 'acknowledged' | 'fixed' | 'ignored';
}
```

#### 内置校验规则示例
| 规则ID | 规则名称 | 校验逻辑 | 严重级别 |
|--------|---------|---------|---------|
| V001 | 资产负债平衡 | totalAssets = totalLiabilities + totalOwnersEquity | error |
| V002 | 利润表平衡 | operatingRevenue - totalCost = netProfit | error |

```typescript
interface FinancialMetric {

    max: number;
```

#### 利润表勾稽关系
```javascript
// 营业利润计算
operatingProfit = operatingRevenue 
                - operatingCost 
                - taxesAndSurcharges 
                - sellingExpenses 
                - administrativeExpenses 
                - (financialExpenses - interestIncome + interestExpense)
                - assetImpairmentLoss 
                - creditInvestmentIncome 
                + gainsFromChangesInFairValue 
                + investmentIncome 
                + assetDisposalIncome;

// 利润总额
totalProfit = operatingProfit + nonOperatingIncome - nonOperatingExpense;

// 净利润
netProfit = totalProfit - incomeTaxExpense;
```

### 详细业务流程说明

#### 1. 报表上传阶段 (Pages 01 → 02)
**触发条件**: 用户在小程序首页点击"扫描/拍照"或"上传PDF"

**前置条件**:
- 用户已登录
- 设备摄像头/文件访问权限已授权

**处理步骤**:
1. **文件采集**
   - 相机拍照: 调用 `wx.chooseImage`, 支持连拍最多9张
   - PDF上传: 调用 `wx.chooseMessageFile`, 限制≤20MB
   - 相册选取: 支持从相册选择已有图片

2. **前端预处理**
   - 图片压缩: 限制最大分辨率2048px, JPEG质量85%
   - 格式转换: PNG→JPEG减小体积
   - 文件完整性校验: MD5校验防止传输损坏

3. **上传至服务器**
   - 调用 `POST /api/v1/upload` 接口
   - 支持断点续传(大文件)
   - 返回 taskId 用于后续进度跟踪

4. **跳转进度页**
   - 携带 taskId 跳转到 [02 识别与解析进度] 页面

**异常处理**:
- 网络中断: 本地缓存，恢复后自动重传
- 文件过大: 提示压缩或分批上传
- 格式不支持: 跳转 [11 不相关内容提示] 页面

---

#### 2. 识别与解析阶段 (Page 02)
**触发条件**: 文件上传成功，服务端开始处理

**处理流程**:
1. **图片预处理服务端** (预计耗时2-5秒)
   - 图像增强: 去噪、倾斜矫正、对比度增强
   - 版面分析: 检测表格区域、标题、页眉页脚
   - 区域裁剪: 提取有效表格区域

2. **OCR文字识别** (预计耗时5-15秒)
   - 引擎选择: 根据文档质量自动选择最优引擎
   - 多引擎融合: 结合2-3个OCR引擎结果提高准确率
   - 置信度打分: 每个字符/词赋予置信度分数

3. **表格结构解析** (预计耗时3-8秒)
   - 单元格检测: 识别表格线、合并单元格
   - 行列重建: 还原逻辑表格结构
   - 跨页处理: 处理跨页表格的拼接

4. **字段映射匹配** (预计耗时2-5秒)
   - 模糊匹配: 使用编辑距离算法匹配字段名
   - 上下文推断: 根据相邻字段推断当前位置
   - 多准则校验: 结合位置、名称、数值特征综合判断

5. **数据校验** (预计耗时1-3秒)
   - 执行30+条内置校验规则
   - 生成校验结果报告
   - 标记异常项

6. **报告生成准备** (预计耗时3-10秒)
   - 计算30+财务指标
   - 生成五维健康度评分
   - 准备AI分析所需的结构化数据

**进度反馈机制**:
- **轮询模式** (默认): 每2秒客户端主动查询 `/api/v1/progress/{taskId}`
- **WebSocket模式** (可选): 服务端实时推送进度更新事件
- **超时保护**: 单个任务最长运行时间5分钟，超时自动终止

**状态码定义**:
```typescript
enum TaskStatus {
  PENDING = 'pending',           // 排队中
  PROCESSING = 'processing',     // 处理中
  COMPLETED = 'completed',       // 完成
  FAILED = 'failed',             // 失败
  CANCELLED = 'cancelled'        // 已取消
}
```

#### 3. 建档与信息补充阶段 (Page 03)
**触发条件**: 
- 首次上传某企业的报表（系统中无该企业档案）
- 或用户主动新建企业

**表单数据校验**:
1. **企业名称**
   - 必填，长度2-100字符
   - 禁止纯数字、特殊字符
   - 支持中英文、括号

2. **统一社会信用代码**
   - 必填，固定18位
   - 格式校验: 登记管理部门代码(1位)+机构类别(1位)+登记管理机关行政区划码(6位)+主体标识码(9位)+校验码(1位)
   - 唯一性校验: 系统内不可重复

3. **报告期间**
   - 必填，年份范围2020-2030
   - 季度: 1-4 或 月份: 1-12
   - 默认值: 当前季度

4. **会计准则口径**
   - 必填，单选:
     - 企业会计准则 (CAS): 适用于大中型企业
     - 小企业会计准则 (SES): 适用于小微企业

5. **报表类型**
   - 多选，至少选择一项
   - 选项: 资产负债表 / 利润表 / 现金流量表

**智能辅助功能**:
- 信用代码自动查询: 输入后调用工商API获取企业全称
- 历史期间推荐: 根据已有报表推荐下一期间
- 重复检测: 提示是否已存在相同期间的同类报表

**数据持久化**:
- 保存至 enterprises 表 (企业基础信息)
- 生成 reports 记录 (报表元数据)
- 关联上传的原始文件和识别结果

#### 4. 识别结果复核阶段 (Page 04)
**触发条件**: OCR识别和字段映射完成

**页面加载逻辑**:
1. 请求 `GET /api/v1/reports/{reportId}/fields` 获取字段列表
2. 按报表类型分组展示 (Tab切换)
3. 按置信度降序排列 (低置信度优先显示)
4. 统计各等级字段数量

**置信度等级划分**:
| 等级 | 范围 | 颜色 | 建议操作 |
|------|------|------|---------|
| 高可信 | ≥90% | 绿色 (#e8f8f4) | 可直接确认 |
| 中可信 | 70-89% | 黄色 (#fff8e1) | 建议核对 |
| 低可信 | <70% | 红色 (#ffebee) | 必须人工确认 |

**复核操作流程**:
1. **逐项浏览**: 上下滑动浏览字段列表
2. **查看原文**: 点击字段行，右侧滑出原图并高亮对应区域
3. **在线修正**: 
   - 点击数值单元格进入编辑模式
   - 弹出数字键盘 (小程序) 或输入框 (Web)
   - 支持千分位输入，自动去除逗号
   - 实时格式校验: 只允许数字、负号、小数点
4. **批量操作**:
   - "全部通过": 将所有 pending 状态字段标记为 confirmed
   - "导出修正列表": 导出Excel供线下修正后导入

**数据提交**:
- 调用 `PUT /api/v1/reports/{reportId}/fields` 提交修正数据
- 服务端重新执行校验规则
- 跳转至 [06 数据校验与异常中心]

**性能优化**:
- 虚拟滚动: 仅渲染可视区域字段 (字段数通常100+)
- 懒加载: 原图按需加载
- 缓存策略: 已确认字段本地缓存

**交互功能**:

#### 6. 数据校验与异常处理阶段 (Page 06)
**触发条件**: 报表数据提交后自动触发

**校验规则执行引擎**:

1. **规则分类执行** (并行):
   ```
   Thread-1: 平衡性检查 (V001-V003)
   Thread-2: 逻辑一致性 (V004-V010)
   Thread-3: 比率合理性 (V011-V020)
   Thread-4: 趋势异常 (V021-V025)
   Thread-5: 完整性检查 (V026-V030)
   Thread-6: 格式规范性 (V031-V035)
   ```

2. **结果聚合**:
   - 统计各级别数量: passed / warning / error / skipped
   - 生成问题清单，按严重程度排序
   - 关联相关字段，便于快速定位

3. **异常项展示**:
   - 卡片式布局，每条异常一个卡片
   - 包含: 规则名称、问题描述、当前值、期望值、建议操作
   - 颜色编码: 🔴Error / ⚠️Warning / ℹ️Info

4. **处理工作流**:
   - **确认已知**: 标记为 acknowledged (特殊情况，如经审计调整)
   - **在线修正**: 跳转到字段复核页面对应字段
   - **忽略**: 标记为 ignored (需填写原因，仅管理员权限)
   - **重新校验**: 修正后重新执行全部规则

**内置校验规则详解** (部分示例):

| 规则ID | 名称 | 公式/逻辑 | 严重级别 | 说明 |
|--------|------|----------|---------|------|
| V001 | 资产负债平衡 | \|资产总计 - (负债+权益)\| ≤ 1 | Error | 基本会计恒等式 |
| V002 | 利润表平衡 | \|营业收入-成本-费用-税±调整-净利润\| ≤ 1 | Error | 利润计算准确性 |
| V003 | 现金流量平衡 | \|净增加额+期初-期末\| ≤ 1 | Error | 现金流水核对 |
| V004 | 营收大于零 | 营业收入 > 0 | Warning | 正常经营应有收入 |
| V005 | 成本小于营收 | 营业成本 < 营业收入 | Warning | 成本不应超过收入 |
| V006 | 流动比率合理 | 0.5 ≤ 流动比率 ≤ 3.0 | Warning | 过低偿债风险，过高资金闲置 |
| V007 | 资产负债率安全 | 资产负债率 ≤ 80% | Warning | 过高杠杆风险 |
| V008 | 存货非负 | 存货 ≥ 0 | Error | 存货不能为负数 |
| V009 | 货币资金非负 | 货币资金 ≥ 0 | Error | 资金不能为负数 |
| V010 | 应收账款非负 | 应收账款 ≥ 0 | Error | 应收不能为负数 |
| V011 | 净资产非负 | 所有者权益 ≥ 0 | Warning | 资不抵债风险 |
| V012 | 环比变动合理 | \|(本期-上期)/上期\| ≤ 50% | Info | 剧烈波动需关注 |
| ... | ... | ... | ... | ... |

**校验结果持久化**:
- 保存至 validations 表
- 关联 report_id 和 field_ids
- 记录处理状态和时间戳
- 支持历史追溯

#### 7. 财务健康度评分阶段 (Page 07)
**触发条件**: 数据校验通过 (无Error级别问题或已处理)

**评分模型架构**:

```
输入: 标准化的三大报表数据
  ↓
┌─────────────────────────────────────────────┐
```

**单指标评分算法**:
```python
def calculate_indicator_score(value, benchmark, industry_avg, is_higher_better):
    """
    计算单个指标的得分 (0-100)
    
    参数:
    - value: 企业实际值
    - benchmark: 理论最优值或行业标准
    - industry_avg: 行业平均值
    - is_higher_better: 数值方向 (True=越高越好, False=越低越好)
    """
    
    # 1. 计算偏离度
    if is_higher_better:
        deviation = (value - benchmark) / benchmark
    else:
        deviation = (benchmark - value) / benchmark
    
    # 2. 转换为分数 (使用Sigmoid函数平滑映射)
    import math
    raw_score = 100 / (1 + math.exp(-5 * deviation))
    
    # 3. 边界约束
    score = max(0, min(100, raw_score))
    
    # 4. 特殊处理极端值
    if value <= 0 and is_higher_better:
        score = 0  # 负值或零值直接判0分
    
    return round(score, 1)
```

**维度聚合算法**:
```python
def calculate_dimension_score(indicator_scores, weights):
    """
    计算维度加权平均分
    """
    weighted_sum = sum(score * weight for score, weight in zip(indicator_scores, weights))
    total_weight = sum(weights)
    
    return round(weighted_sum / total_weight, 1) if total_weight > 0 else 0

# 示例: 偿债能力维度
solvency_indicators = [current_ratio_score, quick_ratio_score, cash_ratio_score, ...]
solvency_weights = [0.25, 0.25, 0.20, 0.15, 0.15]  # 各指标在维度内权重
solvency_dimension_score = calculate_dimension_score(solvency_indicators, solvency_weights)
```

**综合评分计算**:
```python
# 最终加权
overall_score = (
    solvency_score * 0.30 +
    profitability_score * 0.25 +
    cash_flow_score * 0.20 +
    efficiency_score * 0.15 +
    growth_score * 0.10
)

# 确定等级
if overall_score >= 80:
    level = "healthy"
elif overall_score >= 60:
    level = "attention"
elif overall_score >= 40:
    level = "warning"
elif overall_score >= 20:
    level = "danger"
else:
    level = "critical"
```

```python
def detect_trend_alerts(time_series_data, rules_config):
    """
    检测趋势异常并生成预警
    """
    alerts = []
    
    for metric, values in time_series_data.items():
        # 规则1: 连续N期下降
        if is_continuous_decline(values, n=rules_config.get('consecutive_periods', 3)):
            alerts.append({
                'metric': metric,
                'type': 'continuous_decline',
                'severity': 'warning',
                'data': values[-rules_config['consecutive_periods']:]
            })
        
        # 规则2: 超出阈值范围
        if is_out_of_range(values[-1], rules_config.get('threshold')):
            alerts.append({
                'metric': metric,
                'type': 'out_of_range',
                'severity': 'danger',
                'value': values[-1],
                'threshold': rules_config['threshold']
            })
        
        # 规则3: 波动率异常
        volatility = calculate_volatility(values[-rules_config.get('window', 4):])
        if volatility > rules_config.get('max_volatility', 0.3):
            alerts.append({
                'metric': metric,
                'type': 'volatility',
                'severity': 'info',
                'volatility': volatility
            })
    
    return sorted(alerts, key=lambda x: x['severity'])
```

### 核心技术难点与解决方案

#### 1. OCR识别准确率提升
**挑战**: 财务报表常存在印章遮挡、手写批注、表格线干扰等问题

**解决方案**:
- 多引擎融合: 同时调用2-3个OCR引擎，取置信度最高结果
- 图像预处理: 去除表格线、印章检测与移除、倾斜矫正
- 上下文纠错: 利用财务字段上下文关系纠正识别错误
- 人工复核兜底: 低置信度字段强制人工确认

#### 2. 表格结构复杂度
**挑战**: 财务报表常有合并单元格、嵌套表、跨页表格

**解决方案**:
- 版面分析: 使用深度学习模型检测表格区域
- 单元格重建: 基于表格线的形态学处理
- 合并单元格识别: 分析文字对齐关系推断合并区域
- 模板匹配: 针对标准报表格式使用模板辅助解析

#### 3. 字段映射准确性
**挑战**: 不同企业报表格式差异大，字段命名不统一

**解决方案**:
- 模糊匹配: 编辑距离算法 + 同义词词典
- 位置先验: 利用标准报表的字段位置规律
- 多维特征: 结合字段名、位置、数值特征、相邻字段综合判断
- 机器学习: 训练分类模型预测字段类型

#### 4. 性能与并发
**挑战**: OCR处理耗时长 (单份报表10-30秒)，并发量大时易阻塞

**解决方案**:
- 异步处理: 上传后立即返回taskId，后台异步处理
- 消息队列: 任务队列削峰填谷
- 分布式处理: 多节点并行处理OCR任务
- 缓存策略: 识别结果缓存，相同文件不重复处理
- 进度反馈: WebSocket实时推送处理进度

#### 5. 数据安全与隐私
**挑战**: 财务数据敏感，涉及企业商业机密

**解决方案**:
- 传输加密: HTTPS/TLS 1.3
- 存储加密: AES-256数据库字段级加密
- 访问控制: RBAC角色权限模型
- 审计日志: 记录所有数据访问和操作
- 数据脱敏: 导出/展示时敏感字段脱敏
- 合规: 符合《数据安全法》《个人信息保护法》要求
